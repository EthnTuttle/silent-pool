Short summary: how it works

Nix builds the rbitcoin node, Silent Pool services and a self-hosted captaind Ark server from pinned sources. The lab supervisor creates private configuration, assigns local ports, starts isolated storage for each pool and the Ark server, and records observations for the operator pages. Native mining, native bootstrap funding and unfunded Ark infrastructure have been verified in scoped runs; the complete funded mining-to-Ark flow is still being built.

The intended complete flow is: CPU miners receive authenticated SV2 jobs, search real SHA256d headers within the declared hash budget, and submit shares to pool fronts. rbitcoin decides which blocks are valid. Mature native funding outputs supply the transaction actors, which sign ordinary fee-paying traffic and fund the local Ark wallets. Pool accounting assigns earnings to fixed-value coinbase outputs and Ark remainders; the separate Ark role executes signed orders, and each miner's wallet scans, receives, refreshes and offboards its funds. Those final joined payout and wallet steps remain under verification.

Final experiment target: two nodes, two pools, four miner processes and four SPc wallets, eight background payment wallets, one local Ark server, two pool Ark roles and three PostgreSQL clusters. The independent controls are 40 H/s aggregate mining and 0.2 ordinary transactions per second. Smaller recorded component fixtures have their own explicit populations.
